Android SDK). So verification was split into what *could* be tested and what can't:

| Check | How | Result |
|---|---|---|
| Gameplay logic (fair level generation, passengers, difficulty, saves, collision maths) | `dotnet test unity/Tests.DotNet` (NUnit, same files as the Unity EditMode tests) | **35/35 pass** |

| Jumpability | Every jumpable obstacle is cleared by the configured jump at the slowest speed it can appear | pass |
| Procedural meshes | Index validity, normal length, triangle winding vs normals, 16-bit index limit, footprint vs collider | pass |

## Deviations from the spec, and why
* **UI Toolkit instead of uGUI + TextMeshPro.** UI Toolkit is built into Unity 6 and needs no TMP
  font-asset generation step. It could also be compile-checked here. Every screen is built in code (`UIManager`).
* **Custom chase camera instead of Cinemachine.** It implements every listed behaviour (follow,
  tilt, acceleration FOV, collision shake, jump) without a package dependency.
* **Volumes on AudioSources instead of an AudioMixer asset.** Mixer assets can't be created from
  code. The music and SFX toggles work through the AudioManager.
* **Procedural models instead of imported FBX files.** Everything is original and generated in
  code from the reference photos. They are clean low-poly cartoon models, not sculpted
  commercial-grade art. An artist can replace them later through `ModelLibrary` without touching gameplay.
* **No Missions button on the main menu.** Missions are a Phase 2 feature and the rules forbid
  non-functional buttons. The **Garage** works: it lets you choose between the two liveries from
  your reference images, with a live 3D preview, and the choice is saved.
* **Passenger delivery** (destinations and fares) is left for Phase 2, as the spec asks. To keep
  pickups meaningful once the jeepney is full, riders get off by themselves after 1–3 stops and free their seats.
* **LOD and baked lighting.** Not used. Distant geometry is hidden by fog and the scene is fully
  dynamic, so there is nothing to bake. Shadows are limited by the graphics setting.

## Known risks to check first in Unity
1. **Materials.** Run *Setup Project* before testing on a device. It creates material assets that
   reference the URP shaders. Without them, a build may strip `Universal Render Pipeline/Lit` and
   objects render pink.
2. **UI Toolkit runtime theme.** The panel uses an empty theme because all styling is inline.
   Check that text renders with the bundled TTF fonts on device.
3. **Physics triggers.** The player and hazards both use kinematic rigidbodies with trigger
   colliders. Hits, coins and PARA zones depend on `OnTriggerEnter` firing.
4. **Editor API names** compiled against 2021-era reference assemblies. Some calls may print
   obsolete-API warnings in Unity 6. Treat any *error* as a bug to fix.
5. **Input.** The Input System branch (`ENABLE_INPUT_SYSTEM`) couldn't be compile-checked; the legacy-input branch was.
